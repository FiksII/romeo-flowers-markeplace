# Загрузка и просмотр фото

Пользователь поручил реализовать обсуждённый подход и проверить dev без дополнительных согласований.

Фото каталога: существующий sorl-thumbnail/Pillow, WebP quality 75, ширины 320/400/600/800; sizes соответствует сетке. Первые четыре карточки загружаются eagerly. Детальные превью сохраняют quality 80. Оригиналы сохраняются.

S3 остаётся закрытым. Только выданные приложением подписанные имена изображений доступны через стабильный /photos/ URL на домене сайта. Django Signer проверяет имя, FileBasedCache хранит байты в отдельной закрытой папке (1000 записей, 30 дней). Успешные ответы получают public max-age=2592000, immutable, ETag; ошибки не кешируются. Тело ограничено 8 МБ. Подпись не разрешает произвольные URL, обход путей или чтение иных типов файлов. Новый снимок получает новое имя. Кеш прогревается до переключения dev.

Просмотр: готовый HTML dialog, уже используемый проектом. Фото открывается внутри сайта, с закрытием/Escape, кнопками и стрелками, свайпом, счётчиком; одно фото также открывает диалог. Загрузка большого фото происходит при открытии. Native dialog обеспечивает фокус и модальность. Это небольшая интеграция существующих API, без дополнительной библиотеки.

Подходы: одно сжатие не устраняет задержку S3 и меняющиеся URL. CDN требует отдельной инфраструктуры; используем существующие Django cache/storage. PhotoSwipe изучен, но для требуемого просмотра достаточно существующих dialog и галереи; отдельная зависимость и обязательные размеры оригиналов не нужны.

Проверки: стабильность URL, подпись/обход путей, cache hit без S3, conditional GET/HEAD, отсутствие кеширования ошибок, новые размеры, одно/несколько фото и клавиатура/мобильный диалог. Ветка fix/photo-loading от актуального develop, merge, тесты, полный релиз develop с backup/migrate/collectstatic, прогрев кеша и HTTPS/browser проверки. Затем продвижение develop в master без production deploy.

Результат браузерной проверки первого dev: полноэкранное окно получало тяжёлый PNG-оригинал. Для устранения этой задержки оно использует отдельную WebP-копию quality 80, вписанную в 1600×1600 без обрезки и увеличения. Исходный файл сохраняется; новая регрессия проверяет пропорции, размер и неизменность оригинала.
