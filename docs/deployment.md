## Форма оплаты nonPCI по PaymentURL — 18 октября 2026 года

кнопка переводит на `PaymentURL` из `Init`, как в

разблокирует кнопку и запускает проверку статуса; обычный возврат банка
сохранил `GetState`. Скрипт `payment.js?v=5`, без `integration.js`.

Перед выкладкой исходные версии всех изменяемых файлов сверены с сервером.

`ca53385b2db819fddb8b6b26e45ee61457511dcea7a39ab15bd99567e718da38`.
Резервная копия базы, media, окружения и пути прежнего релиза:
`/srv/backups/romeo-marketplace-before-nonpci-20261018-070716`.
На новом релизе прошли 413 тестов (4 проверки PostgreSQL пропущены), Django
check, проверка миграций, `migrate` и `collectstatic`. Локально — 13 проверок
JavaScript и Ruff. После переключения: HTTPS 200, точная контрольная сумма
нового JS, активные приложение и таймер, поддельное уведомление получает 403.
На рабочей PostgreSQL в откатываемой транзакции проверены создание платежа
на 1 ₽ через DEMO-терминал, JSON `PaymentURL`, редирект без JavaScript,

в базе не сохранены; списание денег не проводилось.

Проверено в браузере: подключённый DEMO-терминал открывает только карту;
публичное демо банка использует ту же форму с логотипом и быстрой оплатой.
Внешний вид и дополнительные способы задаются в кабинете Т-Банка:
«Магазины → Терминалы → Настроить → Универсальное», затем
«Приём оплаты → Готовая платёжная форма от Т-Банка → Настроить».

`pay.tbank-online.com` и откатила заказ. Предыдущая попытка (релиз `…-tbank-polling`)
откатилась сама из-за ошибки сертификата.

локально, платёж `CONFIRMED`). Карты `2201 38…` из документации банка на

## Управление

Настройки Beget S3, перенос фото и порядок возврата к локальному хранилищу описаны


Разовые Django-команды запускать из `/srv/romeo-marketplace/current` с явным `--settings=romeo_market.preview_settings` и от пользователя приложения. Для реальных продаж потребуется закончить платёжную интеграцию, проверить лимиты адресного сервиса и перейти на `romeo_market.production_settings` без демо.
