# Бот MAX

MAX использует те же правила заказов, оплаты и добавления букетов, что Telegram.
Канал настраивается отдельно; Telegram и ВК продолжают работать со своими привязками.

## Подключение

В закрытом окружении приложения нужны `MAX_BOT_TOKEN` и `MAX_BOT_USERNAME`.
Имя можно получить через SDK `get_me`; токен нельзя хранить в репозитории.
`SITE_URL` должен указывать на HTTPS-адрес текущего окружения.

После выкладки кода и миграции выполните от пользователя приложения:

```sh
.venv/bin/python manage.py setup_messengers --channel max --settings=romeo_market.preview_settings
```

Команда проверяет имя бота, подключает только webhook MAX
`/messengers/max/webhook/` и команды `/start`, `/stop`, `/add`, `/cancel`.
Она не перенастраивает Telegram и ВК. Вебхук проверяет секрет из заголовка
`X-Max-Bot-Api-Secret`; секрет вычисляется на сервере и не выводится в консоль.

## Для магазина

Откройте «Настройки» → MAX. Добавьте номер получателя и передайте человеку его
ссылку-приглашение. Номер служит подписью: уведомления получает чат, открывший
одноразовую ссылку. Приглашение действует семь дней. Можно добавить до десяти
номеров на канал, проверить отправку, выключить уведомления, удалить номер или
выдать новую ссылку. Новая ссылка отзывает прежнюю привязку и право добавления.

Право «Разрешить добавление букетов» выдаётся отдельно для каждого привязанного
чата. Приглашение на уведомления не выдаёт это право автоматически.
Бот предлагает выбрать магазин, если доступно несколько, затем фото (до 20,
изображениями или файлами, каждое до 5 МБ), название, описание, категорию,
цветы, теги, размеры, цены и наличие. Для собственной доставки магазина нужны
также цены с доставкой. Доступны «Назад», отмена, предварительный просмотр,
публикация или сохранение скрытым. Товар создаётся обычной формой сайта.

## Для администратора

Личная привязка MAX находится в настройках администратора. Уведомления о доставке
Ромео приходят из отмеченных магазинов, как в Telegram: с фото, получателем,
телефоном, конечной точкой или ссылкой её уточнения и инструкцией об оплате.
Наличный заказ приходит сразу; онлайн-заказ — после подтверждённой оплаты.
Инструкция партнёру не поручает получать наличные при доставке. Для неоплаченного
самовывоза указана сумма к получению; для подтверждённой онлайн-оплаты — получать
деньги с клиента не нужно.

## Реализация и обслуживание

Используется MIT-библиотека `maxapi` из [форка, проверенного командой MAX](https://github.com/max-messenger/max-botapi-python),
зафиксированного на `4a286baa06d38f2db9f7244d94f89508743f8fee`.
Python 3.13 совместим с её требованием Python >=3.10; Pydantic ограничен версией 2.
SDK сохраняет сериализацию, модели и загрузку вложений. Адаптер соединения
использует актуальный [MAX API](https://dev.max.ru/docs-api):
`https://platform-api2.max.ru`, заголовок Authorization и проверку TLS обычными
доверенными корнями с добавлением уже используемого корневого сертификата Минцифры.
Отдельный HTTP-сервер или polling-процесс не нужен.

Входящие события сохраняются в `MaxBotEvent` до ответа 200. Обработка выполняется
после commit, под блокировкой диалога. Повтор одного события не создаёт второй
букет; черновики и права изолированы по каналу. Ответ сохраняется до отправки,
поэтому сетевой повтор не выполняет действие заново. Неотправленные ответы и
уведомления повторяет существующий `send_notifications` из минутного таймера.
После пяти неудачных попыток событие помечается failed; тип последней ошибки
виден в поле error без токенов и приватных URL. Как и большинство HTTP Bot API,
повтор после неопределённого сетевого исхода может повторить сообщение, но не товар.

MAX ограничивает одно сообщение 12 вложениями, поэтому большие галереи делятся
на несколько сообщений. Ошибка обработки ещё не готового вложения остаётся
повторяемой; постоянная ошибка фото не скрывает текст заказа и инструкцию об оплате.
Загрузка входящих фото ограничена доменами MAX, публичными DNS-адресами, размером
5 МБ и запретом перенаправлений. Фактическое изображение проверяет ProductForm.

При отключении токена выключается только MAX. Миграция добавляет канал к
существующим черновикам Telegram со значением по умолчанию telegram и создаёт
отдельную таблицу входящих событий. Данные привязок Telegram и ВК сохраняются.
