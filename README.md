# Цветы от Ромео · маркетплейс

Базовая версия для Москвы и Московской области на Django 5.2 и Django Oscar 4.2. Старый проект `../shop` не изменён. Палитра, шрифты, логотип и фотографии перенесены из его исходных материалов.

## Запустить локальное демо

Нужны Python 3.13 и [uv](https://docs.astral.sh/uv/). Из этой папки:

```powershell
uv sync
uv run python manage.py migrate --settings=romeo_market.demo_settings
uv run python manage.py seed_marketplace --with-accounts --settings=romeo_market.demo_settings
uv run python manage.py runserver 127.0.0.1:8000 --settings=romeo_market.demo_settings
```

Откройте http://127.0.0.1:8000/. Демо использует отдельную `.demo.sqlite3`, три вымышленных магазина и 12 букетов. Повторная загрузка примеров не меняет цены, товары и пароли существующих пользователей.

| Аккаунт | Назначение | Пароль только для локального демо |
|---|---|---|
| `buyer` | Покупатель | `Romeo-demo-2026` |
| `partner` | Магазин «Лепесток» | `Romeo-demo-2026` |
| `operator` | Супер администратор | `Romeo-demo-2026` |

Подсказки адресов в демо работают для трёх примеров: Москва, Тверская улица, дом 1; Химки, Московская улица, дом 1; Балашиха, проспект Ленина, дом 1. Введите часть адреса и выберите подсказку. Точные адреса новых магазинов в демо ограничены этими примерами; в рабочем окружении используется DaData.

## Заполнить кабинеты историей за несколько недель

Из папки `marketplace` выполните:

```powershell
.\scripts\populate-demo.ps1
```

Скрипт применяет миграции к отдельной `.demo.sqlite3` и создаёт 20 покупателей, по одному аккаунту для трёх магазинов, супер администратора, реквизиты-примеры и **168 общих заказов за шесть недель**. У некоторых заказов несколько частей магазинов и единый адрес доставки. Есть доставка, самовывоз, завершённые и текущие заказы, отмены, имитация возвратов и еженедельных выплат. Для завершённых исторических продаж остатки пополняются на проданное количество; текущие заказы сохраняют рабочий резерв.

| Аккаунт | Что смотреть |
|---|---|
| `buyer`, `buyer02` … `buyer20` | История покупок, состав заказов, получение |
| `partner` | Кабинет «Лепестка» |
| `partner_garden` | Кабинет «Тихого сада» |
| `partner_morning` | Кабинет «Доброго утра» в Химках |
| `operator` | Сводная статистика, все магазины и заказы |

Пароль **новых** аккаунтов: `Romeo-demo-2026`. Уже существующие пароли, цены, статусы заказов и магазинов сохраняются. Пустые поля демо-профилей заполняются. Повторный запуск пропускает созданные заказы, добавляет наступившие демо-выплаты по полученным заказам и при новой дате добавляет недостающие дни. Новые примеры могут использовать изменённые вами цены и расписание. Если демо-магазин отключён или его товары/интервалы недоступны, загрузка откатывается целиком и сообщает причину.

В кабинете выберите период 7, 30, 42 или 90 дней: доступны график продаж, цены покупателей и магазинов, наценка, отдельная сумма доставки, возвраты, демо-выплаты и задолженность по полученным заказам. Последняя рассчитана за всё время; остальные показатели — за выбранный период. Продажи и наценка показываются по дате создания заказа; выплаты — по дате условного перечисления.

График построен на [Chart.js 4.5.1](https://www.chartjs.org/docs/latest/), таблицы — на [DataTables 3.1.3](https://datatables.net/). Есть поиск, сортировка и страницы по 20, 50 или 100 записей. Таблица заказов запрашивает данные с сервера: поиск охватывает весь выбранный период и только доступные пользователю магазины. Библиотеки поставляются локально в `static/vendor`, без обращения к CDN при просмотре. Без JavaScript остаются таблица ежедневных продаж и обычная пагинация заказов.

Объём и последнюю дату можно задать явно:

```powershell
.\scripts\populate-demo.ps1 -Weeks 8 -OrdersPerDay 6 -EndDate '2026-10-06'
# Или напрямую, включая начальное значение генератора сценариев:
uv run python manage.py seed_demo_history --weeks 6 --orders-per-day 4 --seed 2026 --settings=romeo_market.demo_settings
```

Команда разрешена только при `MARKET_DEMO=True`. Суммы оплаты, возвраты, реквизиты из нулей и записи `DemoPayout` — вымышленные примеры. Эти записи не являются платёжным реестром и не отображаются как выплаты при выключенном демо-режиме. Реальные провайдеры и деньги не используются. Старое заполнение `seed_marketplace` по-прежнему создаёт только каталог и, с `--with-accounts`, три основных аккаунта.

Для просмотра запустите сервер и откройте http://127.0.0.1:8010/operator/ или http://127.0.0.1:8010/partner/:

```powershell
uv run python manage.py runserver 127.0.0.1:8010 --settings=romeo_market.demo_settings
```

## Цены, наценка и доставка

Магазин задаёт **базовую цену** букета. Супер администратор отдельно для каждого магазина задаёт процент наценки, стоимость доставки Ромео и скидку за самовывоз. Партнёр видит базовую цену, цену на сайте и цену самовывоза, но не меняет настройки платформы.

Цена товаров с доставкой = база магазина + процентная наценка. **Доставка оплачивается отдельной суммой по каждому магазину**, сверх цены цветов; процент на неё не начисляется. Доставку организует Ромео. При самовывозе доставка равна нулю; скидка уменьшает нашу наценку, сохраняя полную базовую сумму магазину.

Начальные настройки демо: наценка 10%, скидка за самовывоз 50% от наценки. Например, база 1 000 ₽ → цветы с доставкой 1 100 ₽ плюс отдельная доставка; самовывоз 1 050 ₽. Магазину в обоих случаях рассчитано 1 000 ₽. Стоимость доставки в демо различается по магазинам. Все суммы округляются до копеек на единицу товара и фиксируются при оформлении; последующие изменения цен не меняют уже созданный заказ. Миграция сохраняет финансовые суммы заказов прежней версии и их прежние условия доставки.

## Что работает

- Просмотр без адреса, времени и авторизации. Необязательная панель места/времени на главной и в каталоге; контекст сохраняется в сессии.
- Поиск, фильтры по цветам, категории, цене, магазину и получению; сортировка и страницы каталога.
- Доставка по радиусу от магазина; предварительный поиск по выбранному городу. Подсказки и серверная проверка ограничены регионами 77 и 50.
- Работа магазина, доставка и самовывоз имеют отдельные недельные расписания и исключения по датам. Ночные интервалы и круглосуточная работа поддержаны. Сборка учитывает только рабочее время; доступное получение показывается в часовых интервалах на 30 дней вперёд.
- Одна корзина из нескольких магазинов. Получение и время выбираются по каждому магазину, адрес доставки общий. Можно совместить доставку и самовывоз.
- Один родительский заказ Oscar, отдельные части магазинов, неизменные базовые и розничные суммы товаров, скидки, наценка, доставка и расчётная доля магазина. Повторная отправка оформления возвращает тот же заказ.
- Резерв остатков, проверка доступности при оформлении, отмена своей неоплаченной части. Резерв действует 30 минут. При запросах сайта очистка запускается раз в минуту; отдельная команда позволяет выполнять её по расписанию без посетителей.
- Покупатель: регистрация, вход, история и детали своих заказов. Партнёр: товары, фото, базовые цены, остатки, реквизиты, зона обслуживания, расписание, свои заказы и статистика. Супер администратор: модерация, наценка, цена доставки, скидка самовывоза, доступ к каждому кабинету, журнал изменений, Django admin.

## Оплата — следующий этап

Приём денег, сплит, возвраты и реальные выплаты **не подключены**. При оформлении создаётся общий заказ со статусом ожидания оплаты. Доля магазина рассчитана, но не записывается как проведённая выплата. Неоплаченные заказы нельзя передать на исполнение.

Для следующего этапа потребуется договор маркетплейса с выбранным российским платёжным провайдером, подключение каждого получателя, проверка реквизитов, единый платёж с распределением по частям, проверяемые и идемпотентные webhook, фискализация и возвраты. Наличие ИНН и счёта в кабинете само по себе не подключает продавца к платёжному сервису.

## Рабочее окружение

1. Создайте новую PostgreSQL-базу. Скопируйте `.env.example` в `.env` и заполните отдельные значения: случайный `SECRET_KEY` (50+ символов), `DATABASE_URL`, реальные `ALLOWED_HOSTS`, токен [DaData](https://dadata.ru/api/suggest/address/).
2. Запускайте команды и сервер с `--settings=romeo_market.production_settings`. Этот модуль требует PostgreSQL и отдельный секрет, отключает демо, включает HTTPS и защищённые cookies. За обратным прокси `TRUST_PROXY_HTTPS=True` допустим только при очистке входящего заголовка прокси.
3. Выполните миграции, `createsuperuser` и `collectstatic`. Создайте населённые пункты регионов 77/50 через `/admin/`. Магазины подключаются через `/partner/new/` и публикуются супер администратором через `/operator/`.
4. Задайте три расписания магазина и проверьте адрес, цены и остатки до активации. Для расписания 24/7 используйте 00:00–24:00; если конец раньше начала, интервал переходит на следующие сутки. Дата-исключение перекрывает в этот день и ночной хвост предыдущего дня.
5. Выполняйте `uv run python manage.py expire_reservations --settings=romeo_market.production_settings` каждую минуту отдельным планировщиком. Для нескольких серверов нужен общий кэш и централизованный планировщик. Статические файлы и `media/` отдаёт веб-сервер; загрузки — локальные изображения JPEG/PNG/WebP до 5 МБ. Резервное копирование БД и media требуется до реальных заказов.

Демо SQLite подходит для просмотра и тестов. Конкурирующие оформления, отмена и изменение товара проверены на изолированном PostgreSQL 17; SQLite не поддерживает `SELECT FOR UPDATE`. Перед запуском повторите проверки на целевом PostgreSQL и под ожидаемой нагрузкой. Реальный запуск продаж требует завершённой платёжной интеграции. Уведомления, полигональные зоны/маршруты, вместимость временных слотов и промокоды в эту базовую версию не включены.

## Проверки

```powershell
uv run python -m pytest -q -p no:cacheprovider
uv run python manage.py check --settings=romeo_market.test_settings
uv run python manage.py makemigrations --check --dry-run --settings=romeo_market.test_settings
uv run python -m ruff check .
uv run python -m ruff format --check .
```

Тесты используют отдельную SQLite-базу в памяти. Проверяют границы региона, подписанные адреса, расписания, составные заказы, остатки и отмены, повторную отправку, доступ к чужим данным и HTTP-сценарий оформления.

Четыре проверки реальной конкуренции пропускаются на SQLite. Чтобы выполнить весь набор на **отдельном тестовом PostgreSQL** (Django создаёт и удаляет `test_…` базу; никогда не указывайте рабочую базу):

```powershell
$env:MARKET_TEST_DATABASE_URL='postgresql://TEST_USER:TEST_PASSWORD@127.0.0.1:15432/romeo_marketplace_tests'
uv run python -m pytest --ds=romeo_market.postgres_test_settings -q -p no:cacheprovider
```

Тесты воспроизводят одновременную покупку последнего товара, дублирующее оформление, отмену во время покупки и изменение товара во время покупки. Подготовка проверяется также при пересечении ночного расписания с часами следующего дня.

## Устройство проекта

`romeo_market/` — настройки и маршруты. `market/` — магазины, права, адреса, расписания, каталог, заказ по магазинам и кабинеты. Oscar владеет товарами, остатками, корзиной и общим заказом; его стандартные checkout/dashboard маршруты не опубликованы, чтобы не обходить проверки маркетплейса. `templates/market/` и `static/market/` — страницы и поведение. `static/storefront/` — исходная визуальная система Ромео.
