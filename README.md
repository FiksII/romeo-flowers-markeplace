# Цветы от Ромео · маркетплейс

Базовая версия для Москвы и Московской области на Django 5.2 и Django Oscar 4.2. Оформление общее с `../shop` (design v2): `static/storefront/css/theme.css` + `romeo.css` одинаковы в обоих проектах, правьте их вместе; слой маркетплейса — `static/market/market.css`. Палитра, шрифты, логотип и фотографии перенесены из его исходных материалов.

## Запустить локальное демо

Нужны Python 3.13 и [uv](https://docs.astral.sh/uv/). Из этой папки:

```powershell
uv sync
uv run python manage.py migrate --settings=romeo_market.demo_settings
uv run python manage.py seed_marketplace --with-accounts --settings=romeo_market.demo_settings
uv run python manage.py runserver 127.0.0.1:8000 --settings=romeo_market.demo_settings
```

Откройте http://127.0.0.1:8000/. Демо использует отдельную `.demo.sqlite3`, три вымышленных магазина и 12 букетов. Повторная загрузка примеров не меняет цены, товары и пароли существующих пользователей.

| Аккаунт | Назначение | Пароль только для локального демо |
|---|---|---|
| `buyer` | Покупатель | `Romeo-demo-2026` |
| `partner` | Магазин «Лепесток» | `Romeo-demo-2026` |
| `operator` | Супер администратор | `Romeo-demo-2026` |

Подсказки адресов в демо работают для трёх примеров: Москва, Тверская улица, дом 1; Химки, Московская улица, дом 1; Балашиха, проспект Ленина, дом 1. Введите часть адреса и выберите подсказку. Точные адреса новых магазинов в демо ограничены этими примерами. В рабочем окружении адреса ищет DaData (если задан токен) или, без токена, бесплатный поиск OpenStreetMap (Nominatim): ключ не нужен.

## Заполнить кабинеты историей за несколько недель

Из папки `marketplace` выполните:

```powershell
.\scripts\populate-demo.ps1
```

Скрипт применяет миграции к отдельной `.demo.sqlite3` и создаёт 20 покупателей, по одному аккаунту для трёх магазинов, супер администратора, реквизиты-примеры и **168 общих заказов за шесть недель**. У некоторых заказов несколько частей магазинов и единый адрес доставки. Есть доставка, самовывоз, завершённые и текущие заказы, отмены, имитация возвратов и еженедельных выплат. Для завершённых исторических продаж остатки пополняются на проданное количество; текущие заказы сохраняют рабочий резерв.

| Аккаунт | Что смотреть |
|---|---|
| `buyer`, `buyer02` … `buyer20` | История покупок, состав заказов, получение |
| `partner` | Кабинет «Лепестка» |
| `partner_garden` | Кабинет «Тихого сада» |
| `partner_morning` | Кабинет «Доброго утра» в Химках |
| `operator` | Сводная статистика, все магазины и заказы |

Пароль **новых** аккаунтов: `Romeo-demo-2026`. Уже существующие пароли, цены, статусы заказов и магазинов сохраняются. Пустые поля демо-профилей заполняются. Повторный запуск пропускает созданные заказы, добавляет наступившие демо-выплаты по полученным заказам и при новой дате добавляет недостающие дни. Новые примеры могут использовать изменённые вами цены и расписание. Если демо-магазин отключён или его товары/интервалы недоступны, загрузка откатывается целиком и сообщает причину.

## Кабинет магазина

Четыре раздела (`/partner/<магазин>/`):

| Раздел | Что внутри |
|---|---|
| **Дашборд** | Сводка по букетам (всего, в продаже, распродано, скрыто), график продаж, суммы за период, демо-выплаты, заказы магазина |
| **Букеты** | Все букеты: в продаже, распроданные (количество 0), скрытые. Цена самовывозом, цена с доставкой (только у магазинов со своей доставкой), количество: число или «всегда в наличии» |
| **Информация о магазине** | Название, адрес с картой, телефон, самовывоз / доставка / своя доставка, подготовка, расписания **работа / доставка / самовывоз по дням недели** одной таблицей, особые даты |
| **Реквизиты и зона доставки** | Реквизиты для переводов (юрлицо, ИНН, счёт, БИК), зона доставки: многоугольник, нарисованный на карте, минимальная сумма, города доставки |

**Букеты.** Количество: число или флажок «Всегда в наличии». Для него используется штатный механизм Oscar: класс товара без учёта остатков (`track_stock=False`). Oscar сам не резервирует и не списывает такой товар, он всегда доступен. Менять режим нельзя, пока есть незавершённые заказы с этим букетом. Распроданный букет (0) остаётся в кабинете и пропадает из каталога, пока магазин не пополнит количество.

**Карты без ключей.** Карта: [Leaflet 1.9.4](https://leafletjs.com/) с тайлами OpenStreetMap, зона рисуется [Leaflet-Geoman 2.20.2](https://geoman.io/leaflet-geoman); обе библиотеки лежат в `static/vendor`, регистрация и ключи не нужны. Тайлы `tile.openstreetmap.org` рассчитаны на умеренную нагрузку ([правила](https://operations.osmfoundation.org/policies/tiles/)); при большом трафике нужен свой источник тайлов. Яндекс Карты без API-ключа не работают, поэтому не используются.

**Адрес.** Выбор адреса из подсказок сохраняет точные координаты, маркер на карте перемещается. Подсказки: DaData при заданном `DADATA_TOKEN`, иначе Nominatim OpenStreetMap: только дома в регионах 77 и 50, не чаще одного запроса в секунду с `User-Agent` из `OSM_USER_AGENT`, ответы кэшируются на 5 минут. Отключить поиск OpenStreetMap: `OSM_ADDRESS_SEARCH=False`. Публичный Nominatim не рассчитан на высокую нагрузку; для неё нужен DaData или собственный сервер.

**Зона доставки.** Многоугольник из 3–100 точек в пределах Москвы и области, стороны не пересекаются. Покупатель с точным адресом видит доставку магазина, только если адрес внутри зоны (граница входит). Без нарисованной зоны точный адрес не подходит ни под какую доставку, дашборд предупреждает об этом. Покупатель, выбравший только город, видит магазин по «городам доставки».

На дашборде выберите период 7, 30, 42 или 90 дней: доступны график продаж, цены покупателей и доля магазинов, комиссия, отдельная сумма доставки, возвраты, демо-выплаты и задолженность по полученным заказам. Последняя рассчитана за всё время; остальные показатели — за выбранный период. Продажи и комиссия показываются по дате создания заказа; выплаты — по дате условного перечисления.

График построен на [Chart.js 4.5.1](https://www.chartjs.org/docs/latest/), таблицы — на [DataTables 3.1.3](https://datatables.net/). Есть поиск, сортировка и страницы по 20, 50 или 100 записей. Таблица заказов запрашивает данные с сервера: поиск охватывает весь выбранный период и только доступные пользователю магазины. Библиотеки поставляются локально в `static/vendor`, без обращения к CDN при просмотре. Без JavaScript остаются таблица ежедневных продаж и обычная пагинация заказов.

Объём и последнюю дату можно задать явно:

```powershell
.\scripts\populate-demo.ps1 -Weeks 8 -OrdersPerDay 6 -EndDate '2026-10-06'
# Или напрямую, включая начальное значение генератора сценариев:
uv run python manage.py seed_demo_history --weeks 6 --orders-per-day 4 --seed 2026 --settings=romeo_market.demo_settings
```

Команда разрешена только при `MARKET_DEMO=True`. Суммы оплаты, возвраты, реквизиты из нулей и записи `DemoPayout` — вымышленные примеры. Эти записи не являются платёжным реестром и не отображаются как выплаты при выключенном демо-режиме. Реальные провайдеры и деньги не используются. Старое заполнение `seed_marketplace` по-прежнему создаёт только каталог и, с `--with-accounts`, три основных аккаунта.

Для просмотра запустите сервер и откройте http://127.0.0.1:8010/operator/ или http://127.0.0.1:8010/partner/:

```powershell
uv run python manage.py runserver 127.0.0.1:8010 --settings=romeo_market.demo_settings
```

## Цены, комиссия и доставка

Магазин сам задаёт цены букета: **цену самовывозом** (она есть всегда) и, если у магазина **своя доставка**, **цену с доставкой**. Покупатель платит ровно эту цену, наценка сверху не добавляется. Без своей доставки покупатель с доставкой тоже платит цену самовывоза, а доставка Ромео добавляется отдельной суммой.

**Комиссия платформы**: процент от цены букета, супер администратор задаёт его для каждого магазина (по умолчанию 10%). Она удерживается из доли магазина: магазину причитается цена минус комиссия. Партнёр видит комиссию в заказе, но не меняет её.

- **Доставка Ромео** (нет своей доставки): стоимость задаёт супер администратор для каждого магазина, она оплачивается сверх цены цветов, процент на неё не начисляется и в долю магазина не входит.
- **Своя доставка**: стоимость доставки входит в цену с доставкой, плата Ромео не берётся, в заказе доставка помечена «Магазин». Если цена с доставкой не указана, покупатель платит цену самовывоза (кабинет подсказывает, у каких букетов её нужно заполнить).
- Пока покупатель не выбрал способ получения, каталог показывает цену с доставкой.

Например, цена самовывозом 2 500 ₽, комиссия 10%: покупатель платит 2 500 ₽ (+ доставка Ромео 350 ₽), магазину причитается 2 250 ₽, комиссия 250 ₽. Комиссия округляется до копеек на единицу товара; суммы фиксируются при оформлении и не меняются при последующем изменении цен, комиссии и доставки.

**Миграция со старой схемы** (наценка и скидка за самовывоз): цена самовывоза становится прежней ценой самовывоза для покупателя, комиссия равна доле прежней наценки в этой цене (например, наценка 10% и скидка 50%: цена база × 1,05 и комиссия 4,76%), поэтому покупатель и магазин получают те же суммы, что и раньше. Прежний радиус доставки превращается в многоугольник-окружность вокруг магазина. Созданные заказы не пересчитываются.

## Что работает

- Просмотр без адреса, времени и авторизации. Необязательная панель места/времени на главной и в каталоге; контекст сохраняется в сессии.
- Поиск, фильтры по цветам, категории, цене, магазину и получению; сортировка и страницы каталога.
- Доставка по зоне-многоугольнику магазина; предварительный поиск по выбранному городу. Подсказки и серверная проверка ограничены регионами 77 и 50.
- Работа магазина, доставка и самовывоз имеют отдельные недельные расписания и исключения по датам. Ночные интервалы и круглосуточная работа поддержаны. Сборка учитывает только рабочее время; доступное получение показывается в часовых интервалах на 30 дней вперёд.
- Одна корзина из нескольких магазинов. Получение и время выбираются по каждому магазину, адрес доставки общий. Можно совместить доставку и самовывоз.
- Один родительский заказ Oscar, отдельные части магазинов, неизменные суммы товаров, комиссия, доставка и расчётная доля магазина. Повторная отправка оформления возвращает тот же заказ.
- Резерв остатков, проверка доступности при оформлении, отмена своей неоплаченной части. Резерв действует 30 минут. При запросах сайта очистка запускается раз в минуту; отдельная команда позволяет выполнять её по расписанию без посетителей.
- Покупатель: регистрация, вход, история и детали своих заказов. Партнёр: кабинет из четырёх разделов (см. выше): букеты с двумя ценами и остатками, информация о магазине с картой и расписаниями, реквизиты и зона доставки, дашборд. Супер администратор: модерация, комиссия, цена доставки Ромео, доступ к каждому кабинету, журнал изменений, Django admin.

## Оплата — следующий этап

Приём денег, сплит, возвраты и реальные выплаты **не подключены**. При оформлении создаётся общий заказ со статусом ожидания оплаты. Доля магазина рассчитана, но не записывается как проведённая выплата. Неоплаченные заказы нельзя передать на исполнение.

Для следующего этапа потребуется договор маркетплейса с выбранным российским платёжным провайдером, подключение каждого получателя, проверка реквизитов, единый платёж с распределением по частям, проверяемые и идемпотентные webhook, фискализация и возвраты. Наличие ИНН и счёта в кабинете само по себе не подключает продавца к платёжному сервису.

## Рабочее окружение

Опубликованное HTTPS-демо и порядок отката описаны в [инструкции развёртывания](docs/deployment.md). Пароли серверных аккаунтов отличаются от локальных примеров.

1. Создайте новую PostgreSQL-базу. Скопируйте `.env.example` в `.env` и заполните отдельные значения: случайный `SECRET_KEY` (50+ символов), `DATABASE_URL`, реальные `ALLOWED_HOSTS`, по желанию токен [DaData](https://dadata.ru/api/suggest/address/) (без него адреса ищет OpenStreetMap, см. выше).
2. Запускайте команды и сервер с `--settings=romeo_market.production_settings`. Этот модуль требует PostgreSQL и отдельный секрет, отключает демо, включает HTTPS и защищённые cookies. За обратным прокси `TRUST_PROXY_HTTPS=True` допустим только при очистке входящего заголовка прокси.
3. Выполните миграции, `createsuperuser` и `collectstatic`. Создайте населённые пункты регионов 77/50 через `/admin/`. Магазины подключаются через `/partner/new/` и публикуются супер администратором через `/operator/`.
4. Задайте три расписания магазина, нарисуйте зону доставки и проверьте адрес, цены и остатки до активации. Для расписания 24/7 используйте 00:00–24:00; если конец раньше начала, интервал переходит на следующие сутки. Дата-исключение перекрывает в этот день и ночной хвост предыдущего дня.
5. Выполняйте `uv run python manage.py expire_reservations --settings=romeo_market.production_settings` каждую минуту отдельным планировщиком. Для нескольких серверов нужен общий кэш и централизованный планировщик. Статические файлы отдаёт веб-сервер; фото товаров JPEG/PNG/WebP до 5 МБ сохраняются локально в `media/` или в S3. Подключение Beget и перенос существующих фото описаны в [инструкции S3](docs/s3-storage.md). Резервное копирование БД и файлов требуется до реальных заказов.

Демо SQLite подходит для просмотра и тестов. Конкурирующие оформления, отмена и изменение товара проверены на изолированном PostgreSQL 17; SQLite не поддерживает `SELECT FOR UPDATE`. Перед запуском повторите проверки на целевом PostgreSQL и под ожидаемой нагрузкой. Реальный запуск продаж требует завершённой платёжной интеграции. Уведомления, маршруты курьеров, вместимость временных слотов и промокоды в эту базовую версию не включены.

## Проверки

```powershell
uv run python -m pytest -q -p no:cacheprovider
uv run python manage.py check --settings=romeo_market.test_settings
uv run python manage.py makemigrations --check --dry-run --settings=romeo_market.test_settings
uv run python -m ruff check .
uv run python -m ruff format --check .
```

Тесты используют отдельную SQLite-базу в памяти. Проверяют границы региона, подписанные адреса, расписания, составные заказы, остатки и отмены, повторную отправку, доступ к чужим данным и HTTP-сценарий оформления.

Четыре проверки реальной конкуренции пропускаются на SQLite. Чтобы выполнить весь набор на **отдельном тестовом PostgreSQL** (Django создаёт и удаляет `test_…` базу; никогда не указывайте рабочую базу):

```powershell
$env:MARKET_TEST_DATABASE_URL='postgresql://TEST_USER:TEST_PASSWORD@127.0.0.1:15432/romeo_marketplace_tests'
uv run python -m pytest --ds=romeo_market.postgres_test_settings -q -p no:cacheprovider
```

Тесты воспроизводят одновременную покупку последнего товара, дублирующее оформление, отмену во время покупки и изменение товара во время покупки. Подготовка проверяется также при пересечении ночного расписания с часами следующего дня.

## Устройство проекта

`romeo_market/` — настройки и маршруты. `market/` — магазины, права, адреса, расписания, каталог, заказ по магазинам и кабинеты. Oscar владеет товарами, остатками, корзиной и общим заказом; его стандартные checkout/dashboard маршруты не опубликованы, чтобы не обходить проверки маркетплейса. `templates/market/` и `static/market/` — страницы и поведение. `static/storefront/` — исходная визуальная система Ромео.

Спецификация: `docs/superpowers/specs/2026-10-06-marketplace-foundation-design.md`. План: `docs/superpowers/plans/2026-10-06-marketplace-foundation.md`.
